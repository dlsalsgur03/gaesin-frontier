# 팀 일정 API

모든 요청은 `access_token` 쿠키 인증이 필요하다. 팀 일정은 그 팀의 **현재 멤버 모두**가
등록·수정·삭제할 수 있다. 멤버가 아니거나 존재하지 않는 팀·일정은 404다.
경로의 ID는 양의 정수 문자열이며 형식이 틀리면 400이다.

## 엔드포인트

- `GET /teams/:teamId/schedules`: 팀 일정 목록 (200, private/no-store). 시작 시각 오름차순, id 오름차순.
- `POST /teams/:teamId/schedules`: 등록 (201)
- `PUT /schedules/:id`: 전체 수정 (200). 생략한 설명은 비우고 종료 시각은 시작과 같게 맞춘다.
- `DELETE /schedules/:id`: 삭제 (200, `{ message }`)
- `GET /calendar/schedules?from=&to=`: 캘린더용. 내가 속한 모든 팀의 일정 중 `[from, to)`에 걸치는 것
  (`startAt < to` 그리고 `endAt >= from`). `from < to`, 최대 62일. (200, private/no-store)

응답은 `{ schedules }`, `{ schedule }`이며 일정은 다음 형태다.

```json
{
  "id": "3",
  "teamId": "14",
  "teamName": "캡스톤 팀",
  "title": "중간 발표 리허설",
  "description": "",
  "startAt": "2026-11-12T06:00:00.000Z",
  "endAt": "2026-11-12T06:00:00.000Z"
}
```

## 본문

| 필드          | 규칙                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| `title`       | 공백 제거 후 1~100자                                                                  |
| `description` | 선택, 최대 10,000자. 공백뿐이면 비운다                                                |
| `startAt`     | 필수. 시간대를 포함한 ISO 8601(`2026-11-12T15:00:00+09:00`, `...Z`). 초·밀리초는 선택 |
| `endAt`       | 선택. 생략·`null`이면 시작 시각과 같게 저장한다(한 시점의 일정). 시작보다 앞서면 400  |

## 시각 규칙 (2026-11-10 사용자 결정)

- 과제의 `YYYY-MM-DD`(UTC 자정) 규약과 달리 일정은 **시각**까지 받는다. 시간대 없는 값은 어느 시각인지 알 수 없어 400이다.
- DB에는 UTC로 저장하고(`TIMESTAMP(3)`), 응답은 항상 UTC ISO(`toISOString()`)다.
- 브라우저는 입력값(`datetime-local`)을 브라우저 시간대로 해석해 ISO로 보내고, 응답을 브라우저 시간대로 바꿔 보여준다.
  캘린더에서 어느 날짜 칸에 놓일지도 브라우저 시간대 기준이다.

일정에는 완료 표시가 없다(2026-11-10 사용자 결정: 완료 체크는 할 일에만 쓴다). 기존 `Schedule` 모델을 그대로 쓰며 스키마 변경은 없다.

## 실시간 알림과 삭제

- 등록·수정·삭제 뒤 `team:changed { scopes: ['schedules'] }`를 팀 룸에 보낸다(`../realtime/README.md`).
- 팀 삭제 트랜잭션이 그 팀의 일정을 먼저 지운다(`../teams/teams.service.ts`).
- 권한 확인 직후 다른 요청이 같은 일정을 지운 경우에도 500 대신 404로 응답한다.

검증: backend에서 `npm run test:schedules`(7개). 접근 차단, 입력 검증, 종료 생략, 정렬, 전체 수정,
캘린더 기간 경계, 다른 팀 분리, 실시간 알림 대상, 팀 삭제 시 함께 삭제를 검사한다.
